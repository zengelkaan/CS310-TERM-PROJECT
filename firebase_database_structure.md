# Firebase Firestore Database Structure

## Overview
PetConnect uygulaması için Firebase Firestore veritabanı yapısı.

---

## Collections

### 1. `users` Collection
Kullanıcı bilgilerini saklar.

**Document ID**: User ID (Firebase Auth UID veya custom ID)

```javascript
{
  uid: string,                    // Unique user ID
  email: string,                  // Email address
  name: string,                   // Full name
  profileImageUrl: string?,       // Profile image URL (optional)
  phoneNumber: string?,           // Phone number (optional)
  location: {
    city: string?,
    address: string?,
    coordinates: {
      latitude: number,
      longitude: number
    }
  },
  createdAt: timestamp,
  updatedAt: timestamp,
  bio: string?                    // User bio (optional)
}
```

**Indexes**: 
- `email` (for email-based queries)
- `createdAt` (for sorting)

---

### 2. `pets` Collection
Pet/Evcil hayvan bilgilerini saklar.

**Document ID**: Auto-generated by Firestore

```javascript
{
  ownerId: string,                // Reference to users.uid
  name: string,                   // Pet name
  kind: string,                   // "Dog", "Cat", "Rabbit", etc.
  breed: string,                  // Breed name
  gender: string,                 // "Male", "Female"
  age: string,                    // e.g., "3 years", "2 months"
  ageInMonths: number?,           // For sorting/filtering
  photos: string[],               // Array of image URLs
  about: string,                  // Description about the pet
  purpose: string,                // "Adoption", "Dating", "Both"
  available: boolean,             // Is available for adoption/dating
  createdAt: timestamp,
  updatedAt: timestamp,
  status: string                  // "active", "adopted", "pending"
}
```

**Indexes**:
- `ownerId` (for user's pets)
- `kind` + `available` (for filtering)
- `purpose` + `available` (for filtering)
- `createdAt` (for sorting)

---

### 3. `feedingPoints` Collection
Beslenme noktaları bilgilerini saklar.

**Document ID**: Auto-generated by Firestore

```javascript
{
  creatorId: string,              // Reference to users.uid (who added it)
  title: string,                  // e.g., "Dormitory", "Faculty of Engineering"
  description: string?,           // Description (optional)
  location: {
    address: string,
    coordinates: {
      latitude: number,
      longitude: number
    }
  },
  imageUrl: string?,              // Photo of the feeding point (optional)
  verified: boolean,              // Is verified by admin
  rating: number?,                // Average rating (1-5)
  ratingsCount: number,           // Number of ratings
  createdAt: timestamp,
  updatedAt: timestamp,
  active: boolean                 // Is still active
}
```

**Indexes**:
- `creatorId` (for user's feeding points)
- `location.coordinates` (Geohash for geo queries - consider using GeoFirestore)
- `verified` + `active` (for filtering)
- `createdAt` (for sorting)

---

### 4. `vaccinations` Collection
Aşı hatırlatıcılarını saklar.

**Document ID**: Auto-generated by Firestore

```javascript
{
  petId: string,                  // Reference to pets document ID
  ownerId: string,                // Reference to users.uid
  title: string,                  // e.g., "Rabies", "DHPP", "FVRCP"
  date: timestamp,                // Vaccination date
  completed: boolean,             // Is completed
  reminderSent: boolean,          // Was reminder sent
  createdAt: timestamp,
  updatedAt: timestamp
}
```

**Indexes**:
- `petId` (for pet's vaccinations)
- `ownerId` (for user's pets' vaccinations)
- `date` + `completed` (for upcoming vaccinations)
- `ownerId` + `completed` + `date` (for reminders query)

---

### 5. `conversations` Collection
Sohbet konuşmalarını saklar.

**Document ID**: Auto-generated by Firestore

```javascript
{
  participants: string[],         // Array of user IDs [userId1, userId2]
  petId: string?,                 // Reference to pets document ID (if conversation is about a pet)
  lastMessage: {
    text: string,
    senderId: string,
    timestamp: timestamp
  },
  unreadCount: {                  // Unread messages per user
    [userId: string]: number
  },
  createdAt: timestamp,
  updatedAt: timestamp
}
```

**Indexes**:
- `participants` (array-contains for user conversations)
- `updatedAt` (for sorting conversations)
- `petId` (for pet-related conversations)

**Note**: For efficient querying, create a composite index on `participants` (array-contains) + `updatedAt`

---

### 6. `messages` Collection (Subcollection)
Mesajları saklar. Her `conversations/{conversationId}/messages` alt koleksiyonunda.

**Document ID**: Auto-generated by Firestore

```javascript
{
  conversationId: string,         // Parent conversation ID
  senderId: string,               // Reference to users.uid
  text: string,                   // Message text
  timestamp: timestamp,
  read: boolean,                  // Is read by recipient
  readAt: timestamp?              // When was read (optional)
}
```

**Indexes**:
- `conversationId` + `timestamp` (for messages in a conversation)
- `senderId` (for user's sent messages)
- `read` + `timestamp` (for unread messages)

---

### 7. `likes` Collection (Optional)
Pet beğenilerini saklar (dating feature için).

**Document ID**: Auto-generated by Firestore

```javascript
{
  userId: string,                 // Reference to users.uid (who liked)
  petId: string,                  // Reference to pets document ID
  createdAt: timestamp
}
```

**Indexes**:
- `userId` (for user's likes)
- `petId` (for pet's likes)
- `userId` + `petId` (unique constraint check)

## Security Rules (Recommended)

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Users can read/write their own data
    match /users/{userId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && request.auth.uid == userId;
    }
    
    // Pets - anyone can read, only owner can write
    match /pets/{petId} {
      allow read: if request.auth != null;
      allow create: if request.auth != null && 
                       request.resource.data.ownerId == request.auth.uid;
      allow update, delete: if request.auth != null && 
                               resource.data.ownerId == request.auth.uid;
    }
    
    // Feeding points - anyone can read, authenticated users can create
    match /feedingPoints/{pointId} {
      allow read: if request.auth != null;
      allow create: if request.auth != null;
      allow update, delete: if request.auth != null && 
                               resource.data.creatorId == request.auth.uid;
    }
    
    // Vaccinations - only owner can access
    match /vaccinations/{vaccId} {
      allow read, write: if request.auth != null && 
                            resource.data.ownerId == request.auth.uid;
    }
    
    // Conversations - only participants can access
    match /conversations/{convId} {
      allow read, write: if request.auth != null && 
                            request.auth.uid in resource.data.participants;
      
      // Messages subcollection
      match /messages/{messageId} {
        allow read, write: if request.auth != null && 
                              request.auth.uid in get(/databases/$(database)/documents/conversations/$(convId)).data.participants;
      }
    }
  }
}
```

## Important Notes

1. **Geo Queries**: For feeding points location queries, consider using GeoFirestore library for efficient geospatial queries.

2. **Real-time Updates**: Use Firestore listeners for real-time updates in chat and notifications.

3. **File Storage**: Use Firebase Storage for images (pets, users, feeding points). Store URLs in Firestore documents.

4. **Pagination**: Implement pagination for large collections (pets, feeding points) using `startAfter()` and `limit()`.

5. **Composite Indexes**: Create composite indexes in Firebase Console for complex queries (e.g., `participants` + `updatedAt` for conversations).
